レベル除外・ロールオークション・YouTube音楽再生を追加

AZQ BOT v2.4 パッチノート / 2026年11月23日

一部のチャンネルやロールでレベル(XP)を付けない設定ができる /levelexclude、ロールそのものをコインで競り落とすロールオークション /roleauction、ボイスチャンネルでYouTubeの音楽を流せる /play を追加しました。レベル除外とオークションの開催は既定では管理者だけが操作でき、ダッシュボードの「機能ごとの必要役職」で、副管理者・幹部・モデレーターなどにも開放できます。あわせて、大きなデータの保存中にBOTが止まって「応答しない」になる問題を減らす軽量化を行いました。

新機能

レベルを付けないチャンネル・ロールの設定 /levelexclude

雑談以外の場所や、BOT用・荒らし対策用のロールなど、レベルを上げたくない場所や人を指定できるようになりました。

/levelexclude channel channel: action: … チャンネルでレベルを「オフにする」/「オンに戻す」。テキスト・ボイス・ステージ・フォーラム・カテゴリを選べます。カテゴリを選ぶと、中のチャンネルとスレッドすべてが対象です。スレッドやフォーラムの投稿は、親チャンネルの設定に従います。

/levelexclude role role: action: … そのロールを持っている人には、どこで発言してもレベルが付きません。@everyone は指定できません(全員のレベルが止まってしまうため)。

/levelexclude list で現在の除外一覧を確認でき、/levelexclude clear で「チャンネル」「ロール」「すべて」をまとめて解除できます。チャンネルとロールはそれぞれ100件まで登録できます。/level config を引数なしで実行したときの現在の設定にも、除外の一覧が表示されます。

除外中は、XPとメッセージ数(ステータス)の両方が増えません。ボイスチャンネルでは、滞在時間とXPが付かなくなります(「2人以上のときだけXPを付ける」の人数にも数えません)。すでに貯まっているXPやレベルは消えません。設定の変更は管理ログに記録されます。

ロールオークション /roleauction(ロールを直接オークション)

アイテムを介さず、ロールそのものをオークションに出せるようになりました。落札した人にそのロールが付きます。入札にはコイン(経済機能)を使います。

/roleauction start role: start_price: … オークションを開催します。次の項目も指定できます。

・minutes: 期間(5分〜7日。既定は24時間)
・buyout: 即決価格(この額以上で入札すると、即決価格で落札)
・days: 落札後にロールが付く日数(1〜365日。省略すると永久。期限が来ると自動で外れます)

/roleauction bid id: amount: … 入札します(誰でもできます)。入札したコインは入札時に預かり、上回られると自動で返却されます。上乗せは現在の最高額の5%以上が必要で、終了間際(60秒以内)の入札があると、終了が60秒延びます。/roleauction list で開催中の一覧、/roleauction cancel id: で中止(入札があれば全額返却)ができます。

開始と結果は、開催したチャンネルに投稿され、落札者と、上回られた人にはDMでも知らせます。落札額は回収されてサーバーのコイン消費になります(誰かに入金されることはありません)。BOTが再起動しても、開催中のオークションは続行され、終了は約20秒以内に処理されます。

安全のための制限があります。強い権限を持つロール、BOTより上位のロール、BOT・連携が管理するロール、自分と同位以上のロールは出品できません。同じロールを同時に2件出すことはできず、同時開催は10件までです。すでに永久でロールを持っている人は入札できません(期限つきロールの保有者は、延長のために入札でき、落札すると残り期間に日数が加算されます)。落札時にロールが付けられなかったとき(ロールの削除・落札者の退出・BOTの権限不足など)は、入札額を全額返却します。

オン/オフは、既存のオークション設定(/economy config auction_enabled:)と共通で、経済機能をオフにしたときや、経済コマンドを使えないチャンネルでは使えません。

誰が操作できるかを設定できる(新しい権限)

次の2つを、役職ごとの権限に追加しました。どちらも既定は管理者(サーバーオーナー・Discordの管理者権限を持つ人・役職の「管理者」)だけです。

・レベル除外(チャンネル・ロール)の設定 … /levelexclude の全コマンド
・ロールオークションの開催・中止 … /roleauction start と /roleauction cancel

Webダッシュボードの「役職・権限」タブにある「機能ごとの必要役職」から、「副管理者以上」「幹部以上」「モデレーター以上」などに変更できます(入札と一覧は、変更に関係なく誰でも使えます)。新しいコマンドは全員のコマンド一覧に表示されますが、権限がない人が実行するとエラーが表示されるだけで、何も変更されません。

YouTubeの音楽を再生 /play

ボイスチャンネルに入って /play query: にYouTubeのURLか検索ワードを入れると、BOTがそのボイスチャンネルに参加して音楽を流します。再生中に実行すると、曲がキューに追加されます(プレイリストのURLを入れた場合は、1曲だけ再生します)。

再生中は、曲名・サムネイル・進行バー・次の曲を表示したパネルが出て、10秒ごとに更新されます。パネルのボタンで、次の操作ができます。

・一時停止 / 再開、スキップ、ストップ(停止して退出)
・ループ再生(いまの曲を繰り返す)
・自動再生(キューが空になったら、関連する動画を自動で流す)
・再生リスト(待機中の曲を最大15曲まで表示)、動画(YouTubeのページを開く)

ボタンは同じボイスチャンネルに入っている人だけが押せます。曲が終わってキューが空になったとき(自動再生がOFFの場合)と、ボイスチャンネルから人がいなくなったときは、BOTが自動で退出します。再生に失敗したときは、理由を書いて退出します。

BOTを動かしているサーバーに、ffmpeg(必須)が必要です。PyNaCl と yt-dlp は、起動時に自動で導入され、/play の初回実行時に yt-dlp が最新版へ更新されます。YouTube側の制限で再生できない場合は、BOTの実行フォルダに cookies.txt を置く(または環境変数 YT_COOKIES でファイルを指定する)と改善することがあります。

その他の変更

動作の軽量化(コマンドが「応答しない」になる問題の対策)

データが増えたサーバーで、保存や集計のあいだBOT全体が数秒止まり、スラッシュコマンドが「応答しない」になることがありました。原因になりやすい処理を、次のように軽くしました。

・データの保存(レベル・経済・サーバー管理・発言の統計)を細かく分けて行い、途中で他の処理に順番を譲るようにしました。
・ランキング(レベル・所持金・ポイント)は、データが変わったときだけ作り直します。
・仮想株は、再起動後の追いつき計算を少しずつ行い、1回の補正の上限を約2.4時間分から30分分に下げました(再起動直後に数秒止まるのを防ぐため)。人気順の保有者数は5秒間まとめて使い回します。経済データの保存の間隔は、3秒から10秒にまとめました。
・起動時に読み込んだ大量のデータを、メモリの定期点検(ガベージコレクション)の対象から外し、点検による一時停止を減らしました。

ボイス接続の診断 ;voicetest

音楽が流れないときの原因調査用です。ボイスチャンネルに入って、チャットに ;voicetest と送ると、BOTが参加して4秒間のテスト音を流し、接続の詳細をログに記録します。

レベル設定の細かな修正

レベル設定の初期値(除外リストなど)が、サーバー間で共有されないようにしました。

アップデート方法

  • GitHub から最新の bot.py をダウンロードして、現在稼働中のものと入れ替えて再起動してください。dashboard.html は今回、変更がありません。
  • 追加の設定は不要です。新しいスラッシュコマンド(/levelexclude /roleauction /play)は、起動時の同期で自動的に反映されます。レベルの除外設定は data/levels.json、ロールオークションは data/economy.json に保存され、既存のデータはそのまま引き継がれます。
  • /play を使うには、サーバーに ffmpeg が入っている必要があります(Ubuntuなら sudo apt install ffmpeg)。
  • レベル除外・ロールオークションの開催を、管理者以外にも許可したいときは、Webダッシュボードの「役職・権限」→「機能ごとの必要役職」で変更してください。
